# ADR-0002

## Title

Initial Reference Implementation and Command Interface

---

## Status

Accepted

---

## Context

ClawForge has established its governing foundation, architectural hierarchy, Orientation requirement, and Integrity-governed change process.

The executable architecture remains intentionally minimal.

Build 0.0.6 — State introduces ClawForge's first executable capability: observing and communicating the state of a ClawForge repository before interpretation, evaluation, or modification begins.

Implementing this capability requires an initial programming language, executable structure, and command interface.

These choices must make ClawForge usable without allowing a temporary implementation technology to become part of ClawForge's permanent identity.

ClawForge must also remain independent of any particular editor. VS Code may be used to develop ClawForge, but ClawForge's executable capabilities must operate on the repository rather than depend upon VS Code.

The command interface should be understandable, durable, and capable of supporting future capabilities such as:

* State
* Orientation
* Integrity evaluation
* verification
* history and durable memory

A short command may improve daily usability, but a convenience alias must not become required for operation or create behavior distinct from the canonical interface.

---

## Decision

ClawForge shall use Python for its first reference implementation.

Python is an initial, replaceable implementation technology. It is not part of ClawForge's identity, governing foundation, or permanent architectural definition.

The first implementation should use the Python standard library where practical and should avoid unnecessary external dependencies.

The canonical executable command shall be:

```text
clawforge
```

The first executable capability shall eventually be invoked as:

```text
clawforge state
```

During development, before installation and packaging are complete, the same capability may be invoked as:

```text
python -m clawforge state
```

ClawForge may also provide the convenience alias:

```text
cf
```

When available, the alias shall expose the same command interface:

```text
cf state
```

The `cf` alias:

* is optional
* must not be required for ClawForge operation
* must not possess behavior distinct from `clawforge`
* may be unavailable where it conflicts with another installed command
* must route to the same implementation and command behavior as the canonical interface

The initial implementation structure should separate:

* command routing
* repository observation
* state representation
* report formatting
* operating-system and Git interactions

The initial State capability shall be read-only.

It shall not:

* depend upon VS Code or another editor
* modify repository contents
* silently refresh remote information
* silently contact GitHub
* infer Known Good State from a clean working tree
* absorb the authority of Orientation or Integrity

Future implementations may replace Python or expose additional interfaces, provided they preserve ClawForge's accepted behavior, evidence requirements, governing boundaries, and canonical command semantics.
