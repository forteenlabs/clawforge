# Current Direction

Build 0.0.6 — State has been completed.

ClawForge now has its first executable capability and accepted architecture for:

- observing local repository state
- explicit remote-state refresh
- governed artifact discovery
- authoritative build-state interpretation
- preservation of missing, stale, unavailable, or contradictory evidence
- declared Known Good State verification
- Python as the first replaceable reference implementation
- `clawforge` as the canonical executable command
- `cf` as an optional equivalent alias
- `python -m clawforge` as a supported development invocation
- separation of State from the authority of Orientation and Integrity

The immediate priority is post-build Orientation and deliberate selection of the next architectural question.

Future builds may address:

- executable Orientation
- machine-readable Integrity Records
- automated session and journal continuity
- higher-level verification and finalization orchestration
- external system and agent conformance
- bounded operation by a verified ClawForge agent

These are possible directions, not active or approved build scope.

There is currently no active build.

The next build must be separately oriented, defined, and evaluated before work begins.
